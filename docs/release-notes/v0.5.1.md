# Spherewright 0.5.1

[English](v0.5.1.md) · [简体中文](v0.5.1.zh-CN.md)

0.5.1 adds individual native wind-turbine recovery and power-impact previews to the0.5 maintenance line. It addresses [Issue #5](https://github.com/Arcueid77/Spherewright/issues/5). The shared implementation also reaches the0.6 development line.

## Wind recovery

Inspect the exact completed2203 turbine and player, then request `spherewright_prepare_dismantle` with `previewOnly=true`. The tokenless `windTurbineDismantle` assessment reports generation capacity loss, projected power components, affected/disconnected consumers and unmet readiness conditions.

A fresh executable prepare binds the endpoint, player and complete native power topology. Commit performs one ordinary DSP removal. Its `windTurbineDismantleReadback` verifies target/node/generator disappearance, exact building recovery, inventory inc, surviving entities/prebuilds/connections and expected power membership. Rebuilding uses a newly prepared normal build with current inventory and placement conditions.

## Compatibility and installation

Windows x64, DSP0.10.35.29151 and BepInEx5.4.17. Use matching Plugin/MCP files from one package. Existing request defaults remain compatible, and the preview/readback additions use protocol1. The Native topology has explicit bounded completeness and split/rearrangement limits. [Protocol](../protocol.md#configuration-transfer-and-dismantle), [Agent playbook](../agent-playbook.md)

The exact source and payload hashes are recorded in `spherewright-manifest.json`. Source/build, installation, gameplay and package records remain source-scoped in the [maintenance validation plan](https://github.com/Arcueid77/Spherewright-Lab/blob/main/scenarios/v0.5.1-wind/implementation-plan.md).
