# Spherewright 0.4.0 release notes — unpublished candidate

0.4 adds bounded observation, planning and native execution for Overseer / Foundry / Governor, and prepares the departure system for later interstellar work. It remains a candidate awaiting owner publication review.

- Production, power, logistics and research observation with diagnostic scope kept separate from execution permission.
- Multi-level Foundry recipe/material/machine/power planning, explicit external supplies and bounded site/dependency estimates.
- Limited blueprint construction with normal materials, drones, per-object progress, cancellation and safe fresh continuation.
- Governor pre-execution production declarations and measured game-tick observations, without autonomous expansion or an unsupported whole-factory balance claim.
- Matching MCP/Plugin protocol surface, an embedded and packaged Agent playbook, and constrained owned-primary version-change disclosures with durable Journal and later explicit confirmation.

The accepted source is `2a7a98d1932c404e3a7abc2c11233d9c0b8780d9`. Both frozen layouts have local installation, runtime and same-version recovery evidence. Product CI passed 3108 tests; package interfaces/playbook and the bounded live acceptance passed. See the [validation summary](../validation/v0.4.0.md) for exact package hashes and the fixed detailed evidence link.

Tested configuration is Windows x64, DSP `0.10.35.29145`, BepInEx `5.4.17.0`, one owned peaceful/non-sandbox/1× local world. Mod Manager/r2modman profile, another-computer use, transaction-crash recovery, broad third-party compatibility and a stationary-carrier-600-tick positive live branch remain unverified. Arbitrary save recovery, multiplayer/combat and interstellar flight/logistics are not added by this release.

The product stays one monorepo. Detailed scenario/runtime evidence moves to a fixed commit of the private Spherewright-Lab consumer repository; product build/test/package remains independent. No tag, Release, publication, deployment or game action is performed by the repository split, and no frozen candidate is regenerated for path changes.
