# 开发经验与避坑

[English](development-lessons.md) · [简体中文](development-lessons.zh-CN.md)

本指南提炼自 Voyager 0.5，供实现与验证参考，不新增审批门、执行权限、资源额度或未变程序的重构建要求。现行仓库规范及 Lab 活动授权仍为准。具体场景事实和原始证据留在 Lab，不复制到本指南。

## 优先处理的问题

| 优先级 | 失败模式 | 改进方法 |
| --- | --- | --- |
| P0 | 单次动作能执行，但部署后才发现后续依赖不成立。 | 先规划完整有用成果：真实矿源、连接、供电、运输、消费、保存及恢复后续运。几何、材料估计和运行前提分别标记已验证、未知或阻塞；依据实际观察细化下一阶段。 |
| P0 | 恢复先只接受空站点，每新增一种已支持建筑或生产状态，又需要一次例外。 | 描述受支持组件的合法状态与转换，包括运行中库存和原生缓存；结合来源与当前实况验证，不假设合法导入状态永远为空或等于启动值。未证组件及绑定仍须拒绝。 |
| P0 | 调用端错误解释可空字段或合法工具结果。 | 按组件类型理解真实公开 DTO。纯供电节点不一定提供耗电设备网络字段；输入口不是输出选择器；进入到达容差不证明路线有实质推进。逐模式验证必需及禁止的请求字段。 |
| P1 | 大量局部测试通过，相同实机生命周期仍反复失败。 | 为受影响转换增加真实状态采集及跨层回归。原生事实的替身须明确标注，不能冒充实机；源码、传输、安装和游戏结果分别证明。 |
| P1 | 每次本地调用错误都触发退世界及恢复。 | 先分类失败再选择恢复方式。停止失败写入批次并保留回执，然后判断纠正后的新鲜批次能否继续使用当前健康绑定。读档有自己的技术成本，不是通用错误处理器。 |
| P1 | 旧指令、旧快照或过程次数覆盖了最新实际状态。 | 中断或交接后刷新检出、锁、活动交接及授权；当前事实保持简洁，历史明确归档。区分授权、原生可执行性、观察覆盖及实际累计资源账。 |
| P1 | 打包、测试或元数据成功被描述为全部交付。 | 每项结论绑定能证明它的证据。载荷一致性、主菜单探测、真实物流循环和冷安装验证各有边界；验收条款采用等价替代时，明确记录被接受的调整。 |

## 验证完整转换

针对受影响状态建立矩阵，不只增加一个孤立的否定谓词：

| 状态或转换 | 重要观察 |
| --- | --- |
| 空站点到已付料施工 | 精确全批实扣、原动作身份、原生实体及双向连接。共享的一次扣料不能按每个对象重复计算。 |
| 待建到物理闲置 | 真实无人机尾返、原开关恢复、已完成/待建对象保留及预算不变。 |
| 已完成站点到未供电连接 | 已知组件成员、合法原生电网拓扑及真实能量状态。有连接不证明有发电。 |
| 采矿及站口入货 | 原矿脉减少、带上货物、站内库存和合法输入缓存变化。启动零库存是来源基线，不是永久不变量。 |
| 保存、主界面及读档 | 完整覆盖当前进度的 owned 档、冲突文件租约释放、正确导入/场景就绪及新鲜自动化准入。存档有效、世界加载就绪、自动化健康是不同事实。 |
| 恢复到继续交付 | 恢复后新的真实运输和消费，同时保留已耗账及原结果。仅加载世界不能证明续运。 |
| 调用端与桥接边界 | 真实 DTO 变体、缺失/不适用值、各模式必需及禁止的标志、解析/变量错误，以及原动作轮询。 |

原生生命周期细节需要直接研究。已退役预建队列的游标可以合法归空；碰撞体集合可能仍在初始化；重新计算的浮点变换不一定逐位相等。修改谓词前核对固定原生实现，保留真实同次观察；未证仍为未知。

## 让调用端可维护

- 可复用 Lab 驱动代码及测试进入版本管理；私有配置、凭据、存档与原回执仍保护并忽略。不可变执行包固定驱动版本和输入，不应逐渐变成独立手改实现。
- 用真实、脱敏的公开响应跑完整调用流程。语法检查不能发现所有变量缺失、模式标志错误或语义假设；schema 正确也不等于运行含义正确。
- 多段移动检查宏观实质推进，将路点间距与到达容差、当前障碍证据联系起来。适用时检查并使用已有采集/取消路径，不反复发送未变化的失败目标。
- 区分 prepared、accepted 与 terminal success。保留原 accepted/unknown 动作及幂等键，换键不能代替核销。

## 按真实失败选择处理方式

| 已观察失败 | 既有授权内的处理 |
| --- | --- |
| 本地准备或调用校验失败，未接受游戏动作 | 保留错误并修调用端；新批次前检查现状，不推断游戏已损坏。 |
| 原生预检拒绝 | 保留拒绝并检查实际谓词，分别诊断产品缺口、调用误用、观察不足或真实预算短缺。授权不能让错误的技术谓词变真。 |
| 已知终态失败，物理停止已证 | 保留该结果。不同的纠正动作须有自己的新鲜证明及适用授权，不改写原失败动作。 |
| 结果未知或绑定丢失 | 保留隔离与原证据，经支持路径核销；不重放、不假定闲置、不覆盖历史。 |
| 准备换源或退出进程 | 操作前证明完整进度覆盖并保全必要输入。支持时使用普通菜单/保存/读档；已授权更新或其他具体技术前提需要时才关闭进程。 |

## 围绕验收成果安排工作

1. 明确整链依赖及下一可测阶段结果；不要在前提未知时锁死远期每个动作。
2. 通过定向测试与跨层回放复现并修正相关源码/调用端缺口，在下次实装前收敛已知关联问题。
3. 按既有构建/CI规则核验准确源码，实机需要时同源安装；观察真实阶段成果，只更新受影响计划。
4. 功能证据闭合后生成最终发行归档。纯文档修订不改变选定运行源，也不要求重新安装或打包。

报告已经达成的结果、首个失败或成功边界、下一项唯一动作及是否确需所有者决定。测试数、提交、备份和压缩包是支持材料，不能代替游戏验收。

## 证据与验收边界

真实观察略低于名义估算时，仍保留原值。浮点或原生整数行为须由实测解释，不能改账或虚增容量；用户固定额度及返航储备仍是限制。

若验收条款要求两包分别安装并验证恢复，载荷逐字节一致与打包主菜单探测本身不能证明完成了这些安装。按约定验证，或记录被接受的范围调整及剩余覆盖；复盘不静默改写原验收结论。
