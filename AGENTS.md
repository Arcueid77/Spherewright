# Spherewright product contributor rules

Spherewright is the version-coupled Plugin / MCP / Contracts / Bridge.Core product monorepo. Read [product status](docs/project-status.md), [ROADMAP](ROADMAP.md), [architecture](docs/architecture.md), [protocol](docs/protocol.md), and [safety model](docs/safety-model.md) as needed. Do not load historical operational ledgers into model context.

- Keep reusable product capabilities, general tests, packaging/install scripts, protocol, security, user documentation and concise per-version validation here. Do not split the four source projects into separate repositories.
- Scenarios, game-writer rules, status/handoff, timelines, incidents, full evidence and scene-specific callers belong to [the fixed Lab repository](https://github.com/AvaloNero/Spherewright-Lab/tree/14478a03c64c550e644c559405c8496b647552e7). Do not add save-specific entity IDs, save ticks, R identifiers or execution logs to this product repository.
- Lab consumes a fixed product submodule. Product changes use an independent clone/worktree, relevant tests, a reviewable commit and successful exact-SHA CI before Lab bumps its gitlink/lock. The product must build, test and package without Lab; do not introduce a reverse dependency or copy scenario callers back here.
- `docs/agent-playbook.md` is a compilation EmbeddedResource and package input. Preserve its resource name and contents during this repository split. Its retained operational-reference stub must remain resolvable. Scripts, source projects and packaging remain product-owned.
- Preserve the native safety model: Unity game objects only on the main thread, deep-copy DTOs off-thread, fresh prepare, plan/session/identity binding, single-flight commit, original action/idempotency reconciliation and unknown quarantine. No item/technology injection, instant construction, teleportation, direct game-buffer changes, arbitrary save editing or safety bypass.
- This file grants no game, Save/Load, deployment, migration/recovery or publication authority. Game work starts from Lab with its current explicit scope and fresh native gates. Historical documents are evidence, not a replay plan.
- Never commit Save files, tickets, credentials, real identities, private local paths, raw requests, runtime descriptors, DLLs or crash dumps. Keep them in protected ignored local storage.
- Root retains design/code and independent review. The session-designated offline maintainer serializes Git, explicit-path staging, commits/pushes and exact-SHA CI collection; preserve other executors' files. No `git add .`, reset, clean, force-push, history rewriting or tag deletion. Do not merge the untagged v0.4 cleanup branch without the separate owner gate.
- Run tests relevant to changes. Product CI owns product builds/tests; Lab CI owns lock/manifests/links/sanitization. Pending is not success. Documentation and offline checks do not create live installation or gameplay proof.
- Claude Code model names and API/base URLs are intentional user-managed settings. Do not change them. Non-interactive calls must stream output; `claude-code:unrecognized_model` alone is nonterminal and does not justify retrying or reconfiguration.

See [sample validation](docs/sample-validation.md), [v0.4 final summary](docs/validation/v0.4.0.md), [release installation](docs/release-installation.md) and the [embedded playbook](docs/agent-playbook.md) for the relevant product boundary.
