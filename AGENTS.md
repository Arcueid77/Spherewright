# Spherewright product contributor rules

[English](AGENTS.md) · [简体中文](AGENTS.zh-CN.md)

Spherewright is the version-coupled Plugin / MCP / Contracts / Bridge.Core monorepo. Read [product status](docs/project-status.md), [documentation](docs/README.md), [ROADMAP](ROADMAP.md), [architecture](docs/architecture.md), [protocol](docs/protocol.md) and [safety](docs/safety-model.md) as needed. Do not load whole historical operational ledgers into model context.

- Keep reusable capabilities, general tests, package/install scripts, protocol, security, user guides and concise per-version validation here. Keep all four source projects together.
- Scenarios, writer scope, status/handoff, timelines, incidents and full evidence belong to [Spherewright-Lab](https://github.com/Arcueid77/Spherewright-Lab). Use [the fixed v0.4 snapshot](https://github.com/Arcueid77/Spherewright-Lab/tree/14478a03c64c550e644c559405c8496b647552e7) for historical proof. Do not copy save-specific entity IDs, ticks, R identifiers or execution logs back here.
- Lab consumes a fixed read-only product submodule. Reusable product changes use an independent clone/worktree, relevant tests, reviewable commits and successful exact-SHA CI before Lab bumps its gitlink/lock. Product builds, tests and packages must not depend on Lab.
- Owner instruction (2026-10-22): use relevant builds/tests during development and install a coherent same-source Plugin/MCP build only when live validation needs it. Do not generate both distribution archives for every edit. Generate the final manual/Thunderstore pair after functional acceptance closes; earlier installation artifacts are development verification inputs, not delivery candidates or progress. Reuse unchanged qualified artifacts; a documentation-only HEAD advance does not automatically change the selected runtime source or trigger repackaging/reinstallation.
- `docs/agent-playbook.md` is an EmbeddedResource and package input. Keep its resource name/URI stable. Changes require matching embedded/package checks; they do not update frozen candidates or installed MCP. Maintain its complete Chinese companion and package language navigation.
- Preserve native safety: Unity objects only on the main thread, deep-copy DTOs off-thread, fresh prepare, exact plan/session/identity binding, single-flight commit, original-action/idempotency reconciliation and unknown quarantine. Never inject items/technology, instantly construct, teleport, edit arbitrary saves or directly write game buffers.
- Owner instruction (2026-10-21): automatically investigate, implement and validate compatibility after DSP updates; do not ask for permission for each version pair. Check the actual native references, save/import formats and affected migration branches, build and test a coherent candidate, and preserve rollback artifacts before cold deployment. This is standing maintenance authority, not a wildcard runtime version bypass: unknown formats, downgrades and incomplete provenance remain blocked. Record only actual Journal adoptions; preserve owned identity, history, expiry, tombstones and fresh prepare/confirmation requirements. Independent Save/Load consent and release authority remain as defined by the active task.
- Documentation grants no game, Save/Load, deployment, migration/recovery or formal-release authority. Game work starts from Lab with explicit scope and fresh native gates. Historical evidence never authorizes replay.
- Never commit Saves, tickets, credentials, private identities/paths, raw private requests, runtime descriptors, DLLs or crash dumps. Keep protected local storage ignored.
- Root owns design and independent review. The designated offline maintainer serializes all Git/gh, explicit-path staging, commit/push and exact-SHA CI collection. Parallel documentation editors own disjoint files and preserve others' changes. Never use `git add .`, reset or clean.
- Prefer separate linear commits without an extra merge commit. Shared-history rewriting needs explicit owner authorization, protected local backup, exact old-to-new mapping and tree checks, and exact-ref `--force-with-lease`; never plain force. Preserve old tags and unrelated work. Subsequent ordinary changes use normal pushes.
- Maintain equivalent English and Simplified Chinese documents, paired `.md` / `.zh-CN.md` or complete inline sections for short redirects/store templates. Preserve code, symbols, identifiers and hashes. Distinguish current guidance, historical research, offline checks and live acceptance.
- Run relevant checks. Product CI owns product build/tests; Lab CI owns locks/manifests/evidence. Pending is not success. Public-repository review includes reachable history and public metadata/logs, not just the latest tree.
- Claude Code model names and API/base URLs are intentional user-managed settings. Do not alter them. Non-interactive calls must stream output; `claude-code:unrecognized_model` alone is nonterminal and does not justify retry or reconfiguration.

See [Lab validation](docs/sample-validation.md), [v0.4 summary](docs/validation/v0.4.0.md), [installation](docs/release-installation.md) and [playbook](docs/agent-playbook.md).
