# 0.5.0 — Voyager development preview

[English](#english) · [中文](#中文)

## English

At archive generation/qualification checkpoint: **Unpublished development preview; not a final Voyager release.** This development/testing slice covers bounded visibility, budget, native flight/stop, warper supply and recovery protection for reviewed validation on DSP `0.10.35.29151`.

- Add the read-only `spherewright_get_voyager_star_catalog` and `spherewright_preview_voyager_route`. Native exploration visibility still applies; pending/hidden resources stay unknown, and permitted normal scans may populate visible scan caches without creating remote factories.
- Preview explicit destination, native units and technology, legitimate fuel/warpers, finite outbound/return windows and protected reserves. Results remain tokenless with `prepared=false`, `executable=false` and `commitAllowedNow=false`; a sufficient budget does not enable flight.
- Add development interfaces `spherewright_prepare_voyager_flight` / `spherewright_commit_voyager_flight` and `spherewright_prepare_cancel_voyager_flight` / `spherewright_commit_cancel_voyager_flight`, reusing the flight/checkpoint coordinator. An explicit visible star marker needs no hidden planet. Return previews/prepares bind the original protected `journeyId` and homebound single-leg reserve; stop requests stay on the original writer and require actual native exit/braking readback.
- Add `spherewright_prepare_supply_mecha_warpers` / `spherewright_commit_supply_mecha_warpers` for one native empty-chamber `Mecha.AutoReplenishWarper` call with exact real-stock count/inc conservation and unchanged automatic setting. Nullable incomplete readback remains unknown; original accepted actions are never repeated under another key.
- Develop native station-warper transfer, bounded read-only carrier details for an existing exact owned factory, and small durable structured-construction controls using the original journey's time/energy reserves. These additions remain under development/offline review and receive no inherited live credit.
- Strengthen flight-checkpoint ticket v2 with exact owned/native/peaceful/tick proof and whole-file evidence, fresh prepare/commit checks and a read-only lease through native adoption. Changed contents, including same-tick replacements, missing strong evidence, expired/retired checkpoints and newer primary progress reject recovery. Legacy v1 flight tickets gain no new recovery authority.
- Retain 0.4 protocol compatibility, existing ordinary action safety, protected-primary confirmation/migration gates, privacy and original-action reconciliation. Never rekey or replay an uncertain accepted action.

At archive generation/qualification checkpoint, current additions are **in development/testing**. The Lab records **2 of 3 historical Voyager gates complete**: resource-return round trip on source `463fc888b1e4cf4a90e08cb1022d2b8896447700`, and controlled failed-flight/exact-checkpoint recovery with newer-primary protection on source `216f4075e983d78fa4d4f5d222bdd279813e1d86`. Sustained cross-star logistics remains open; those source-specific records do not prove this archive or its new additions. The final same-source manual/Thunderstore pair for owner review is still missing. Latest installation and final qualification follow the [Lab active evidence](https://github.com/Arcueid77/Spherewright-Lab/tree/main/scenarios/v0.5-voyager), beyond this checkpoint. Offline tests, source metadata and historical 0.4 acceptance do not close native gates. Exact source/payload hashes belong to this archive's `spherewright-manifest.json`; published 0.4 artifacts and earlier frozen development previews remain unchanged. No 0.5 tag, GitHub Release or Thunderstore upload is authorized or claimed here.

## 中文

**本包生成资格截点：未发布开发预览，不是 Voyager 最终发行。** 此开发/测试切片覆盖面向 DSP `0.10.35.29151` 的有限可见信息、预算、原生飞行/停止、翘曲器补给及恢复保护，用于已审核验证。

- 增加只读 `spherewright_get_voyager_star_catalog` 和 `spherewright_preview_voyager_route`。仍遵守原生探索可见性；未就绪/隐藏资源保持未知，许可的正常扫描可生成可见缓存，不创建远端工厂。
- 预览明确目的地、原生单位与科技、正常燃料/翘曲器、有限去返程窗口和受保护储备。结果无 token，保持 `prepared=false`、`executable=false`、`commitAllowedNow=false`；预算充分不开放飞行。
- 增加开发接口 `spherewright_prepare_voyager_flight` / `spherewright_commit_voyager_flight` 及 `spherewright_prepare_cancel_voyager_flight` / `spherewright_commit_cancel_voyager_flight`，复用 flight/checkpoint 协调器。明确可见恒星标记无需隐藏行星；返程 preview/prepare 绑定原受保护 `journeyId` 与回家单腿储备；停止请求保留原 writer，须读回真实原生退出/刹停。
- 增加 `spherewright_prepare_supply_mecha_warpers` / `spherewright_commit_supply_mecha_warpers`，对原生空舱只调用一次 `Mecha.AutoReplenishWarper`，证明真实库存 count/inc 精确守恒并保持自动设置。未完成读回保持可空未知，原 accepted action 不得换键重做。
- 开发原生站点翘曲器转移、已存在精确 owned 工厂中的有限船只只读详情，以及使用原航程时间/能量储备的小批结构化施工持久控制。这些新增项仍在开发/离线复核，不继承实机信用。
- Flight checkpoint ticket v2 增强精确 owned/原生/和平/tick 与完整文件证据、prepare/commit fresh 重验，以及贯穿原生认领的只读 lease。内容变化（含同 tick 替换）、缺少强证据、检查点过期/退役或较新 primary 覆盖进度均拒绝恢复；旧 v1 flight 票据不获得新恢复权限。
- 保留 0.4 协议兼容、正常动作安全、protected-primary 确认/迁移门、隐私及原 action 核销。结果未知的 accepted action 不得换键或重放。
